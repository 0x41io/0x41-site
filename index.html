> how it works

Three tools. One report.

  1. 01 / find mønømi

    Maps what a domain exposes from public data, and flags the leads worth a closer look.

  2. 02 / prove ʌkʌshi

    Checks each lead: confirmed, ruled out or inconclusive, with the evidence it saw.

  3. 03 / explain kaidøku

    Explains what each proven finding and CVE means, how serious it is and what to fix.

> one command

All three in one pass. Monomi scans, Akashi proves every lead it can, Kaidoku explains the results, and you get one report. Active proofs still wait for your scope file and your yes.

01 / recon

Passive attack surface recon, explained. Monomi maps a domain's public footprint from certificate logs and public data, then Claude explains what it means: what's exposed, what deserves a closer look, and what to fix. Every finding cites numbered evidence, so you can check it yourself.

evidence

Findings are labeled Observed, Inference or Lead, and every one cites its source and collection time.

passive

Reads public data by default and never scans the target. Active checks are opt-in and stay inside your scope.

checks

Subdomains, hosting, open ports and CVEs, email spoofing, subdomain takeover and security headers, plus IP threat-intel.

mcp

Run it as an MCP server so AI agents like Claude can call its checks directly.

02 / proof

Proof before action. Akashi takes Monomi's leads and checks whether each one is really true today, before anyone acts on it. Every lead gets a verdict (confirmed, ruled out or inconclusive) with the evidence behind it and a fix written from what it actually found.

passive first

Proves leads from DNS and public registries by default. Active checks need a scope file and a typed yes, and show every request first.

verdicts

Confirmed, ruled out or inconclusive, each with the reason and the evidence it saw.

fixes

Fix steps built from the records it found for that domain, not a template, with who owns the fix.

recheck

Applied a fix? Re-run the proof to confirm it's closed. Every verdict is kept in a proof history.

03 / explain

Findings and CVEs, explained in plain English. Kaidoku reads Akashi's proven findings and tells you what each one means, how serious it is and what to do next. For CVEs it pulls NVD and CISA's Known Exploited Vulnerabilities catalog, ranks what matters for your stack, and explains exploitability and business impact.

findings

Reads ʌkʌshi's proof history: what's still open, what's fixed, and the next step for each.

ranking

Ranked by CVSS 3.1, with CISA's known-exploited and ransomware flags on top.

profiles

Describe your stack once; in-stack CVEs rank first.

briefings

With --ai, Claude writes a short briefing for each finding and CVE: what it affects and what to do.

> faq

Questions, answered.

Does it touch the target?

Not by default. Monomi reads public certificate logs and public data, and makes standard DNS lookups. Akashi proves leads from DNS and public registries. Anything active (a request to the target's own servers) only runs when you ask for it, stays inside your scope file, and Akashi shows every request and waits for a typed yes first.

Who can I run it on?

Domains you own, or ones you have permission to assess, like a bug bounty program you're in scope for. The scope file uses the same in/out format as a program's page.

What if it finds nothing?

A clean run means these checks found nothing in public data at that moment. It doesn't mean the domain is secure. Trust nothing, verify all, including a clean report.

Does it cost anything?

No. Every tool is free and open source under the MIT license. Optional keys make it better: a free OTX key for more subdomains, an NVD key for faster CVE lookups, and an Anthropic API key only if you want --ai briefings written by Claude (billed by Anthropic to your key).

What do I need to run it?

Python 3.14 and git. The tools aren't on PyPI yet, so you install from GitHub. The 0x41 README pins versions that are tested together. Works on Linux, macOS and Windows.

Can AI agents use it?

Yes. Monomi and 0x41 run as MCP servers, so agents like Claude can call the checks directly. Active checks stay off unless you turn them on, and only reach hosts in a scope file you approved.
